# Evaluación e Identificación del Stack Tecnológico

**Proyecto:** EcoLogística Huancayo — Optimizador de Rutas Sostenibles para "DistriRápido S.A.C."
**Versión:** 1.0.0 | **Fecha:** 28 de agosto de 2026

---

## 1. Evaluación de Alternativas

| Criterio de Evaluación | Alternativa 1: MERN (Node/Express + React + MongoDB) | Alternativa 2: Python / FastAPI + React + PostgreSQL | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
|---|---|---|---|
| Curva de Aprendizaje | Baja (JavaScript unificado en todo el stack) | Media (Python en backend, JavaScript en frontend) | Alta (verboso, fuertemente tipado, mayor tiempo de configuración) |
| Costo de Infraestructura | Moderado (Node async I/O, pero MongoDB exige más RAM para índices geoespaciales a escala) | Bajo (FastAPI asíncrono, bajo consumo de RAM, adecuado para instancias cloud económicas) | Alto (mayor consumo de memoria de la JVM) |
| Soporte Comunitario | Masivo / Muy alto | Alto / crecimiento acelerado, con ecosistema científico maduro (NumPy, SciPy, DEAP) | Masivo / corporativo consolidado |
| Eficiencia Energética / Eco-Design | Media | Alta (FastAPI reporta métricas de cómputo eficientes; Python cuenta con librerías optimizadas para algoritmos metaheurísticos) | Media-baja (tiempo de "warm-up" de la JVM prolongado) |
| Idoneidad para Metaheurísticas (VRPTW/Green VRP) | Baja-media (requiere librerías de terceros menos maduras para optimización combinatoria) | **Alta** — ecosistema Python es el estándar de facto para investigación en optimización (DEAP, OR-Tools, NetworkX) | Media (librerías de optimización disponibles pero con menor tracción en la comunidad académica) |
| Manejo de Datos Geoespaciales | Medio (requiere índices geoespaciales adicionales en MongoDB) | **Alto** (PostgreSQL + extensión PostGIS, estándar para datos georreferenciados) | Alto (PostgreSQL + PostGIS, igual robustez que Alternativa 2) |
| Cumplimiento de Restricción Tecnológica de la Consigna | No cumple (la consigna exige explícitamente Python/FastAPI o similar de código abierto con PostgreSQL) | **Cumple** | No evaluado como prioritario por la consigna |

## 2. Justificación Técnica Formal

El equipo selecciona la combinación **Python (FastAPI) + React.js + PostgreSQL (con extensión PostGIS) + Leaflet/OpenStreetMap** como stack tecnológico definitivo del proyecto EcoLogística Huancayo, por las siguientes razones:

1. **Alineación con la restricción tecnológica de la consigna (RES-06):** el proyecto exige explícitamente tecnologías de código abierto —Python (FastAPI/Django), React.js o Vue.js y PostgreSQL— lo que descarta directamente a MongoDB (Alternativa 1) como motor de base de datos principal.

2. **Idoneidad algorítmica:** la implementación de metaheurísticas para el VRPTW con enfoque Green VRP (RF-003) se beneficia del ecosistema científico de Python (librerías como DEAP para Algoritmos Genéticos, OR-Tools de Google para ruteo de vehículos, y NetworkX para modelado de grafos viales), reduciendo el riesgo de reinventar componentes críticos del algoritmo de optimización.

3. **Manejo de datos geoespaciales:** PostgreSQL con la extensión PostGIS provee soporte nativo para coordenadas GPS, cálculo de distancias reales y consultas espaciales eficientes, requeridas por RF-002 (Registro de Pedidos), RF-003 (Generación de Rutas) y RF-004 (Visualización en Mapa).

4. **Bajo consumo energético en la nube:** FastAPI, al ser asíncrono y de bajo overhead, junto con PostgreSQL optimizado mediante índices (ver Documento 11), favorece directamente el cumplimiento de RNF-010 (Eficiencia Energética / Green Software) y la restricción de Cero Carbono Neto declarada en la consigna original del negocio.

5. **Escalabilidad y perfil del equipo:** React.js en el frontend permite construir tanto la interfaz administrativa (dashboard) como el "modo conductor" simplificado (RNF-005) reutilizando componentes, y FastAPI facilita el despliegue en contenedores con auto-escalamiento horizontal, requerido por RNF-008 (Escalabilidad) ante el crecimiento proyectado de pedidos y distritos atendidos.

6. **Costo de infraestructura acotado:** dado el presupuesto operativo limitado declarado en la consigna del negocio (RES-05), el bajo consumo de recursos de FastAPI y PostgreSQL resulta más compatible con instancias cloud de bajo costo que la alternativa basada en Java Spring Boot.

**Stack tecnológico seleccionado:**

| Capa | Tecnología |
|---|---|
| Backend / API | Python 3.12 + FastAPI |
| Frontend Web (administrativo) | React.js |
| Frontend Móvil / Modo Conductor | React.js (responsive, PWA) |
| Base de Datos | PostgreSQL 16 + extensión PostGIS |
| Motor de Optimización | Python (DEAP / OR-Tools) para Algoritmo Genético y variantes |
| Mapas | Leaflet + OpenStreetMap (con opción de integración a Google Maps API para tráfico) |
| Caché de Sesión | Redis |
| Contenedores / Despliegue | Docker, con orquestación escalable horizontalmente |
