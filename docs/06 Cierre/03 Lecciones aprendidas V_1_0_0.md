# Lecciones Aprendidas

**Fecha:** 2026-10-30 · **Responsable:** Equipo del proyecto

1. Una prueba unitaria no debe depender de internet; OSM pertenece a integración.
2. Una configuración de despliegue no equivale a un despliegue ejecutado.
3. Las evidencias humanas —PR, Jira, firmas y usabilidad— no deben inventarse.
4. Dijkstra resuelve caminos viales; OR-Tools decide asignación y secuencia. Separar ambos conceptos simplifica la explicación.
5. Los indicadores ambientales deben distinguir estimación, línea base y medición real.
6. SQLite/R*Tree y PostgreSQL requieren estrategias de índice distintas pero una API común.
7. CI necesita timeout, concurrencia y artefactos para ser confiable.
8. Las credenciales de demostración deben quedar fuera del build de producción.
9. La documentación de calidad debe nombrar solo herramientas realmente ejecutadas.
10. Un riesgo residual explícito es preferible a afirmar cumplimiento sin evidencia.
